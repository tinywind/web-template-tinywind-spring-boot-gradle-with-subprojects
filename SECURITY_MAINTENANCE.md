# Runtime and security maintenance

Build with JDK 17 and `./gradlew test :webapp:bootWar`. Run the browser helper regression tests with `npm ci` and `npm test`. Gradle output and test fixtures are under `.tmp/`.

The four subprojects remain separate. The supported runtime uses Spring Boot 4.1, Spring Framework 7, Tomcat 11 and Jakarta Servlet APIs. Java package consumers must migrate servlet, validation, annotation and mail imports from `javax` to `jakarta`. JDBC's `javax.sql` package remains unchanged. Jackson 2 is retained for the existing JSON envelope and Vavr data types; Spring's Jackson 2 converter is deprecated and will need replacement before a future Spring major upgrade.

Both datasource configurations and transaction managers remain available. The repository's Oracle migration SQL is unchanged. The Oracle JDBC 11.2 binary is replaced on the runtime classpath by the registry-managed `ojdbc17` driver. Verify the database server against Oracle's JDBC compatibility matrix before using this template with an existing database. No database migration or live Oracle verification was performed during this maintenance.

Set `JDBC_URL`, `JDBC_USERNAME`, `JDBC_PASSWORD`, `SECONDARY_JDBC_URL`, `SECONDARY_JDBC_USERNAME`, `SECONDARY_JDBC_PASSWORD`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME` and `SMTP_PASSWORD` explicitly. Missing credentials fail configuration instead of selecting sample credentials. The datasource URL must use the configured log4jdbc driver, or the corresponding `user-data.datasource.driver-class-name` property must be overridden. Test credentials exist only in `src/test/resources/application-test.yml` and the test fixture configuration. Tests use independent H2 databases in Oracle mode and loopback SMTP/HTTPS/webhook servers. They do not establish Oracle server compatibility.

The file store accepts a single file name, rejects control characters and directory separators, and rejects stored symbolic links. Existing flat stored names remain readable. Uploads retain the original name in database metadata and use a random prefix for the stored name. Storage directories and their parents must be owned and writable only by the application operator; untrusted users must not be able to replace directories. Downloads open the final file without following a symbolic link.

API documentation is available at `/swagger-ui.html` and `/v3/api-docs/application` while `user-data.application.debugging` is true. Existing API payload envelopes, user identifiers, mail rendering, JSP pages and file metadata retain their formats. Collection URLs accept both forms of the existing trailing slash where exercised by the legacy client tests.

MyBatis 3.6.0 replaces 3.5.19 so its internally shaded OGNL copy is updated from 3.4.4 to 3.4.16. The raw dependency advisory scan reports [GHSA-crwc-vw2r-qr6m](https://github.com/advisories/GHSA-crwc-vw2r-qr6m) against OGNL 3.3.4. This template uses OGNL only through Thymeleaf 3.1.5's standard mail template engine. Thymeleaf's maintainer [confirms that Thymeleaf is not affected](https://github.com/thymeleaf/thymeleaf/issues/1058#issuecomment-6484298481), because it does not use OGNL's stricter invocation mode. Forcing OGNL 3.4.13 breaks conditional expressions with `NoSuchMethodError` for the `OgnlContext(MemberAccess, ClassResolver, TypeConverter, Map)` constructor. A regression test evaluates both conditions and method calls through the actual mail engine. The raw finding is retained with this exact scope; no scanner rule or package is ignored. The Gradle binary distribution and wrapper JAR were checked against the [official SHA-256 reference](https://gradle.org/release-checksums/).
